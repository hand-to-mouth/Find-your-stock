# 산업연관표 연관산업 탐색기

2023년 산업연관표(생산자가격·국산 생산유발계수)로 **한 산업을 고르면 그 산업과 연관된 산업을 두 방향으로 찾아주고**, 각 산업에 대응하는 **대표 상장사**를 보여주는 정적 웹앱입니다.

GitHub Pages에 그대로 올릴 수 있도록 **빌드 과정 없는 순수 HTML/CSS/JavaScript**로 만들었습니다. 서버·데이터베이스가 필요 없고, 산업연관표 Excel 파일은 **방문자 브라우저에서 직접 파싱**합니다.

> 대학 「산업조직론」 과제물1 — GitHub를 활용한 산업연관표 분석 웹앱 구축

---

## 1. 무엇을 하는 앱인가

| 단계 | 내용 |
|---|---|
| **STEP 1 자료 불러오기** | **분류 단위(대분류 33 / 중분류 83 / 소분류 165 / 기본부문 380)** 를 고르고 버튼을 누르면 그 단위의 Excel을 내려받아 브라우저에서 읽고 계수를 검증 |
| **STEP 2 원자료 탐색** | 12개 시트를 골라 원자료를 직접 확인·검색 (금액 단위 백만원, 계수 단위 배) |
| **STEP 3 연관산업 분석** | 산업을 고르면 ① 후방연쇄 ② 전방연쇄 두 트랙으로 상위 5개 산업 표시 + **하위 분류로 드릴다운** |
| **STEP 4 대표기업** | 선택한 부문에 대응하는 상장사의 종목명·종목코드·상장시장 표시 |

### 분류 단위를 바꾸면 파일이 바뀝니다

| 분류 단위 | 부문 수 | 읽는 파일 | 드릴다운 |
|---|---|---|---|
| 대분류 | 33 | `io-2023-large.xlsx` (573 KB) | → 중분류 83 |
| 중분류 | 83 | `io-2023-medium.xlsx` (1.2 MB) | → 소분류 165 |
| 소분류 | 165 | `io-2023-small.xlsx` (3.0 MB) | → 기본부문 380 |
| 기본부문 | 380 | `io-2023-basic.xlsx` (12 MB) | — (가장 작은 단위) |

단위를 전환해도 **보고 있던 산업의 계통이 유지**됩니다. 분류 계층표(`sector-tree.xlsx`)를 이용해
`C09 → 31 반도체 → 310 반도체 → 3101 개별소자`처럼 내려가고, 다시 올라오면 `C09`로 돌아옵니다.

### 핵심 아이디어

주식시장에서 한 산업이 주목받을 때 관련 산업이 함께 움직이는 현상을, **산업연관표의 생산유발계수**로 후보를 좁히는 도구입니다.

- **① 후방연쇄(Backward)**: 선택 산업에 최종수요가 생길 때 **함께 생산이 늘어나는 산업**. 원료·부품·전력을 공급하는 쪽이 위에 옵니다.
- **② 전방연쇄(Forward)**: 선택 산업의 산출물을 **중간재로 사다 쓰는 산업**. 다른 산업의 생산이 늘 때 선택 산업이 얼마나 필요한지의 순서입니다.

두 트랙을 분리해서 보여주는 이유는, 같은 산업이라도 **공급자로서 끌어당기는 힘**과 **수요자로서 끌려가는 힘**이 다르기 때문입니다.

## 2. 실행 방법

### 로컬에서 보기

`file://`로 직접 열면 브라우저의 보안 정책(CORS) 때문에 Excel을 읽지 못합니다. **간단한 정적 서버**로 열어 주세요.

```bash
# Python이 있는 경우
python -m http.server 8000
# → 브라우저에서 http://localhost:8000 접속
```

### GitHub Pages에 올리기 (과제 제출 절차)

빌드 과정이 없으므로 **파일을 그대로 올리면 끝**입니다. 아래는 실제 화면 순서와 같습니다.

#### 0단계 — 저장소 확인

- **Settings → General → Repository name**: 이 이름이 최종 주소의 일부가 됩니다.
- **공개 범위가 `Public`** 인지 확인합니다. `Private` 저장소는 무료 계정에서 Pages를 쓸 수 없습니다.

#### 1단계 — 올릴 파일 확인 (총 14개, 약 17.4 MB)

```
저장소 최상위/
├── index.html                  ← 반드시 최상위
├── .nojekyll                   ← Jekyll 처리 생략 (교수님 예시와 동일)
├── README.md
├── css/
│   └── style.css
├── js/
│   ├── io.js
│   ├── tree.js
│   └── app.js
└── data/
    ├── manifest.json
    ├── companies.csv
    ├── sector-tree.xlsx
    ├── io-2023-large.xlsx      573 KB
    ├── io-2023-medium.xlsx     1.2 MB
    ├── io-2023-small.xlsx      3.0 MB
    └── io-2023-basic.xlsx     12 MB   ← 가장 큼
```

> 교수님 예시는 `style.css`·`app.js`가 최상위에 평평하게 있지만, 이 프로젝트는 `css/`·`js/`
> 폴더로 나누어 두었습니다. 모든 경로가 상대경로(`./css/style.css`, `./js/app.js`,
> `./data/…`)이므로 **`index.html`만 최상위에 있으면** 폴더 구조와 무관하게 동작합니다.

#### 2단계 — 업로드

1. 저장소의 **Code** 탭 → **Add file** → **Upload files**.
2. **폴더째 끌어다 놓기**: 크롬·엣지·파이어폭스는 탐색기에서 폴더를 끌어다 놓으면
   **하위 폴더 구조가 그대로 유지**됩니다. `css`, `js`, `data` 폴더를 각각 끌어다 놓으면 됩니다.
3. ⚠️ **zip 파일을 올리면 안 됩니다.** GitHub Pages는 압축을 풀지 않으므로
   `index.html`이 zip 안에 갇혀 페이지가 열리지 않습니다.
4. `data/io-2023-basic.xlsx`(12 MB)는 업로드에 시간이 걸립니다. 진행률이 멈춘 것처럼
   보여도 창을 닫지 말고 기다립니다(웹 업로드 한도는 파일당 25 MB로 여유가 있습니다).

#### 2-1단계 — `.nojekyll` 만들기 (파일 선택창에 안 보일 때)

점(.)으로 시작하는 파일은 업로드 대화상자에서 **숨겨져 보이지 않을 수 있습니다.**
그때는 파일을 올리는 대신 **직접 만듭니다.**

1. **Add file** → **Create new file**
2. 파일 이름 칸에 `.nojekyll` 입력 (앞의 점 포함)
3. 내용은 비워도 되고 `# skip jekyll` 한 줄을 넣어도 됩니다
4. **Commit changes**

#### 3단계 — 구조 검증 (가장 중요)

저장소 첫 화면에서 **`index.html`이 목록 맨 위에 바로 보여야** 합니다.

| 확인 | 정상 | 비정상 |
|---|---|---|
| 최상위에 `index.html` | 보임 | `폴더명/index.html`처럼 한 단계 더 들어가 있음 |
| `data/` 안에 xlsx 4개 | 있음 | xlsx 파일이 최상위에 흩어져 있음 |
| `css/`, `js/` 폴더 | 있음 | `style.css`·`app.js`만 최상위에 있음 |

> **가장 흔한 실패**: 바탕화면의 프로젝트 폴더를 통째로 끌어다 놓아
> `저장소/프로젝트폴더/index.html` 구조가 되는 경우입니다. 이러면
> `https://아이디.github.io/저장소/` 에서 404가 납니다. 이때는 최상위에 있는
> 그 폴더의 파일들을 **한 단계 위로 옮기면** 됩니다(폴더를 지우면 안 되고, 안의 파일을
> 끌어 올린 뒤 빈 폴더를 삭제).

#### 4단계 — Pages 설정

**Settings → Pages** 에서 아래와 같이 설정하고 **Save**:

| 항목 | 선택 |
|---|---|
| Source | **Deploy from a branch** |
| Branch | **`main`** |
| Folder | **`/ (root)`** |

#### 5단계 — 배포 완료 확인

**Actions** 탭 → `pages build and deployment` 워크플로가 **초록 체크**가 될 때까지 기다립니다
(보통 30초~2분, 첫 배포는 더 걸릴 수 있음). 완료 후:

```
https://<사용자명>.github.io/<저장소명>/
```

예: 사용자 이름이 `leeminsu`, 저장소가 `IO_Assignment` 라면
`https://leeminsu.github.io/IO_Assignment/`

#### 6단계 — 동작 점검 (과제 2-5 체크리스트와 1:1 대응)

| 과제 점검 항목 | 이 앱에서 확인할 것 |
|---|---|
| 게시 주소에서 홈페이지가 열림 | 위 주소 접속 → 첫 화면에 STEP 1~4가 보임 |
| Excel 자료를 **버튼을 누른 뒤** 로딩 | 첫 화면에서는 아무 파일도 받지 않고, **자료 불러오기**를 눌러야 로딩 시작 |
| 각 시트·산업을 **구분·검색** | STEP 2의 시트 선택 상자(12개 시트) + 검색창, STEP 3의 산업 검색 |
| 사용 금액·지수의 **단위** 명시 | 화면에 `백만원`(금액) / `배(무차원)`(계수) 표기 |
| 자료 공개 권한·개인정보 | 공개 통계(ECOS)만 사용, 개인정보 없음 — README §4 참고 |
| README에 사용법·분석 방법 | `README.md` §2(사용법) · §5(계산식) |
| **소분류·중분류·대분류·기본부문 4종 모두 활용** | STEP 1의 분류 단위 4버튼 + 드릴다운으로 4단계 전부 사용 |

#### 막혔을 때 (증상별 원인)

| 증상 | 원인 | 해결 |
|---|---|---|
| 주소가 **404** | Pages 설정 전이거나, `index.html`이 최상위가 아님 | Settings → Pages 재확인, 3단계 구조 검사 |
| 화면은 뜨는데 **스타일이 없음** | `css/` 폴더가 안 올라감 | `css/style.css` 경로 확인(`css/style.css`로 접근되는지) |
| **자료 불러오기**가 실패 | `data/` 폴더나 xlsx가 안 올라감 | F12 → Console/Network에서 404 난 파일명 확인 후 재업로드 |
| 글자가 **깨짐** | 파일이 UTF-8이 아님 | 이 저장소 파일은 모두 UTF-8이므로, 편집 후 저장할 때 UTF-8 유지 |
| 수정했는데 **반영 안 됨** | 브라우저 캐시 또는 Actions 진행 중 | 강력 새로고침(`Ctrl+Shift+R`), Actions 초록 체크 확인 |

## 5. 분석 방법 (계산식)

### 5.1 생산유발계수

투입산출표의 생산유발계수 행렬 **B**의 원소 `b(i, j)` 는

> **j산업에 최종수요 1단위가 발생할 때 i산업의 생산이 몇 단위 늘어나는가**

를 뜻합니다. 이 값은 레온티에프 역행렬 `(I − A)⁻¹`에서 구해지며, 한국은행이 이미 계산해 발표한 값을 **그대로 읽어** 사용합니다.

### 5.2 영향력계수 · 감응도계수

| 계수 | 정의 | 위치 |
|---|---|---|
| **영향력계수(j)** | 열합(j) ÷ (전체합 ÷ n) | 시트의 `9801` **행** |
| **감응도계수(i)** | 행합(i) ÷ (전체합 ÷ n) | 시트의 `9802` **열** |

- **1.0 초과** = 전체 평균보다 연쇄효과가 큼
- 정의상 **영향력계수의 합 = n**, **감응도계수의 합 = n** 이어야 합니다.

### 5.3 두 트랙을 뽑는 방법

선택 산업을 **A**, 그 인덱스를 `a`라 할 때

```
① 후방연쇄 top5 :  b(i, a) 가 큰 순서 (i ≠ a)
② 전방연쇄 top5 :  b(a, j) 가 큰 순서 (j ≠ a)
```

**자기 자신을 제외하는 이유**: 대각 원소 `b(a, a)`는 자기 산업에 대한 1단위 생산유발이므로 거의 항상 **1.0보다 크고 해당 열에서 가장 큰 값**입니다. 제외하지 않으면 항상 1위를 차지해 의미 있는 비교가 불가능합니다.
(검증 예: 대분류 C09 컴퓨터·전자·광학기기의 `b(C09, C09) = 1.175039`로 열 최댓값)

### 5.3.1 비중과 누적 비중

각 항목에는 계수와 함께 **비중**과 **누적 비중**을 표시합니다.
"상위 5개가 전체 파급의 어느 정도를 설명하는가"를 보여주기 위한 지표입니다.

```
후방(back):  T = Σ b(i, A)   (i ≠ A)      ← 자기 자신 제외
             비중(i) = b(i, A) ÷ T
             누적(k) = Σ(1위 ~ k위) ÷ T

전방(fwd):   T = Σ b(A, j)   (j ≠ A)
             비중(j) = b(A, j) ÷ T
```

**분모에서 자기 자신을 빼는 이유**: 대각값이 1.0을 넘어 50% 이상을 차지하면
"다른 산업과의 연관"이라는 의미가 흐려집니다. 그래서 **A를 제외한 나머지 n−1개 산업으로
흘러간 파급의 합을 100%** 로 봅니다. 화면의 각주에도 같은 기준을 명시했습니다.

#### 계산 예 (대분류 C09 컴퓨터·전자·광학기기)

| 순위 | 산업 | 계수 | 비중 | 누적 |
|---|---|---|---|---|
| 1 | 제조임가공 및 산업용 장비 수리 | 0.071535 | 13.17% | 13.17% |
| 2 | 도소매 및 상품중개서비스 | 0.060752 | 11.19% | 24.36% |
| 3 | 화학제품 | 0.058703 | 10.81% | 35.17% |
| 4 | 전력, 가스 및 증기 | 0.058591 | 10.79% | 45.96% |
| 5 | 전문, 과학 및 기술 서비스 | 0.051344 | 9.45% | **55.41%** |

→ "상위 5개가 자기 제외 파급의 55.4%를 설명하고, 나머지 27개 산업이 44.6%를 차지한다"로 읽습니다.
같은 산업의 **전방** 누적은 37.1%로, 두 방향의 집중도가 다르다는 점도 드러납니다.

#### 이중 검산 (구현 시 확인)

| 검산 항목 | 결과 |
|---|---|
| 개별 비중의 합 = 상위5 누적 | `0.554133138 = 0.554133138` ✓ |
| 총파급(T) + 자기자신 = 시트의 열합(9590) | `1.718094 = 1.718094` ✓ |
| 총파급(T) + 자기자신 = 시트의 행합(9090) | `1.912518 = 1.912518` ✓ |

즉 비중은 원본 표의 합계 행·열과 정확히 맞물립니다.

### 5.3.2 드릴다운 — 그룹 평균 집계

상위 분류 하나를 **그 자식 부문들의 평균**으로 봅니다. 자식 집합 `M`(크기 `k`)에 대해

```
후방(back):  v_i = (1/k) · Σ_{j∈M} b(i, j)     M 전체에 최종수요 1단위가 생길 때 i의 생산 증가
전방(fwd) :  u_j = (1/k) · Σ_{i∈M} b(i, j)     M 전체의 산출이 필요해질 때 j의 생산 증가
```

**합계가 아니라 평균을 쓰는 이유**: 자식 수가 많은 그룹(예: 화학제품 8개 중분류)이
자식이 적은 그룹(예: 석탄 및 석유제품 1개)보다 자동으로 커지는 것을 막기 위해서입니다.
합계로 집계하면 **분류 체계의 칸 수**가 산업 규모처럼 작동해 버립니다.

#### 그룹 내부 / 그룹 외부 분리

`i ∈ M` 이면 **그룹 내부**(같은 상위 분류 안의 거래), 아니면 **그룹 외부**입니다.

- **트랙(① 후방 / ② 전방)** 에는 **그룹 외부**만 순위로 표시합니다.
- **그룹 내부**는 값이 정의상 크게 나오므로 **별도 표**로 분리했습니다.
- 비중·누적 비중의 분모는 1단계와 같은 원칙으로 **그룹 외부 파급의 합**을 100%로 씁니다.

#### 계산 예 (대분류 C09 → 중분류 6개 그룹)

| 항목 | 값 |
|---|---|
| 그룹 구성 | 31 반도체 · 32 전자표시장치 · 33 기타 전자부품 · 34 컴퓨터 및 주변기기 · 35 통신·방송·영상·음향기기 · 36 정밀기기 (k=6) |
| 그룹 내부 연쇄 합 | 1.2301배 |
| 그룹 외부로 나간 파급 합 | 0.5993배 |
| 그룹 파급 중 내부에서 끝나는 비중 | **67.2%** |
| 후방 외부 상위 5개 누적 | 41.5% |
| 전방 외부 상위 5개 누적 | 18.8% |

→ 전자 부문은 **부품·완제품이 한 그룹 안에서 강하게 맞물려** 있어, 파급의 67%가
그룹 안에서 끝납니다. 반대로 그룹 밖으로는 후방(장비·소재)이 더 넓게 퍼집니다.

#### 교차 검증

그룹 전체 파급은 시트의 합계 행·열과 다음 관계가 성립해야 합니다.

```
후방: (1/k) · Σ_{j∈M} 열합(j)  =  그룹 내부 + 그룹 외부
전방: (1/k) · Σ_{i∈M} 행합(i)  =  그룹 내부 + 그룹 외부
```

측정된 **최대 잔차 4.44e-16** (부동소수점 오차 수준)으로 일치했습니다.
화면의 드릴다운 상태줄에도 같은 값이 표시됩니다.

### 5.4 계수 검증 (앱 내 구현)

화면의 **「계수 검증 결과 보기」** 패널은 두 가지를 확인합니다.

1. **재계산 교차검증** — 시트에 적힌 발표값과, 행렬로 다시 계산한 값(열합÷평균, 행합÷평균)의 최대 차이
   - 측정값: **최대 잔차 1.332e-15** (부동소수점 오차 수준)
2. **합계 항등식** — 영향력계수 합과 감응도계수 합이 모두 n(부문 수)인지
   - 측정값: **33.000000 / 33.000000** (대분류, n=33)

즉 표에 적힌 계수를 신뢰할 수 있음을 화면에서 직접 확인할 수 있습니다.

## 5.5 12개 시트는 무엇이고, 왜 골라야 하나

투입산출표 한 파일에는 **12개 시트**가 있고, 시트마다 담긴 내용이 다릅니다.
성격이 다른 **4개 묶음 × 3개** 구조입니다.

| 묶음 | 시트 | 단위 | 내용 |
|---|---|---|---|
| **거래표** | A표_총거래표(생산자) | 백만원 | 국산+수입을 합친 실제 거래 금액 |
| | A표_수입거래표(생산자) | 백만원 | 그중 수입품만 분리 (해외로 새는 부분) |
| | A표_국산거래표(생산자) | 백만원 | 그중 국산품만 분리 (생산유발계수의 기초) |
| **투입계수** | 총투입계수(A) | 배 | 생산 1단위에 필요한 투입 비율 |
| | 수입투입계수(Am) | 배 | 투입 중 수입 비중 |
| | 국산투입계수(Ad) | 배 | 투입 중 국산 비중 |
| **유발계수** | **생산유발계수** | 배 | **최종수요 1단위 → 생산 파급 (앱의 분석 기준)** |
| | 수입유발계수 | 배 | 최종수요 1단위 → 수입 파급 |
| | 부가가치유발계수 | 배 | 최종수요 1단위 → 부가가치 파급 |
| **항목별 유발액** | 최종수요 항목별 생산유발액 | 백만원 | 소비·투자·수출 항목별 생산유발 실적 |
| | 최종수요 항목별 수입유발액 | 백만원 | 항목별 수입유발 실적 |
| | 최종수요 항목별 부가가치유발액 | 백만원 | 항목별 부가가치유발 실적 |

### 중요한 점: 시트 선택은 분석 결과를 바꾸지 않습니다

STEP 2(원자료 탐색)는 **선택 사항**입니다. STEP 3의 연관산업 분석은
`생산유발계수` 시트를 **코드에서 자동으로** 사용하므로, 목록에서 무엇을 고르든
분석 결과와 대표기업은 달라지지 않습니다.

STEP 2의 목적은 과제 점검항목 **"투입산출표의 각 시트와 산업을 구분하여 파악하고 검색할 수 있어야 함"**
을 충족하는 것입니다. 즉 **분석에 쓰인 값의 근거를 직접 확인하는 용도**입니다.

### 어떤 기준으로 고르면 되나

| 궁금한 것 | 볼 시트 |
|---|---|
| 분석 계수가 어디서 나왔나 | **생산유발계수** (기본 선택됨) |
| 실제 거래 금액 | 총거래표 / 국산거래표 |
| 수입 의존도 | 수입거래표, 수입투입계수(Am) |
| 부가가치 파급 | 부가가치유발계수 |
| 소비·수출이 각각 얼마나 생산을 유발했나 | 최종수요 항목별 생산유발액 |

발표·시연에서는 **`생산유발계수` 한 개만** 보여주면 충분합니다.
나머지는 "이런 원자료도 있다"는 근거 자료입니다.

### STEP 2 ↔ STEP 3 연동 (선택 산업 자동 추적)

"선택이 결과를 바꾸지 않는다"는 점을 보완하기 위해, 두 단계를 연결했습니다.

1. STEP 3에서 산업을 고르면 **STEP 2의 `생산유발계수` 표에서 그 산업의 행이 노란색으로 강조**됩니다.
   표를 검색·재렌더링해도 강조가 유지됩니다(`state.selectedRowCode`).
2. STEP 3 결과 하단의 **「이 산업을 원자료에서 보기 (STEP 2)」** 버튼을 누르면
   `생산유발계수` 시트로 전환하고 **해당 행으로 스크롤**합니다.

이로써 STEP 2는 단순 나열이 아니라 **"분석에 쓰인 그 행의 원자료를 바로 확인하는" 기능**이 됩니다.
즉 과제 점검항목의 *"각 시트와 산업을 구분하여 파악하고 검색할 수 있어야 함"* 을
실제 동작으로 충족합니다.

## 5.4 그룹 내부 연쇄 — 3분해와 기준선

드릴다운에서 그룹 내부 연쇄는 **두 지표**로 표시합니다. 이렇게 나눈 이유와
구간 경계의 근거를 기록해 둡니다.

### 왜 나누는가

생산유발계수의 대각값 `b(m, m)`은 정의상 거의 항상 1.0을 넘습니다. 그래서 그룹 내부
합계를 그대로 보면 **89~99%가 자기 자신**입니다. 실측하면:

| 그룹 | 내부 합 | 그중 대각(자기 자신) | 비대각(타 부문 거래) |
|---|---|---|---|
| 272 열간압연강재 | 1.1023 | 1.0079 (**91.4%**) | 0.0944 |
| C09 전자·광학기기 | 1.2301 | 1.0936 (**88.9%**) | 0.1365 |
| 282 비철금속 1차제품 | 1.0183 | 1.0121 (**99.4%**) | 0.0061 |
| 401 자동차 | 1.0000 | 1.0000 (**100.0%**) | 0.0000 |

즉 **내부 비중만 보면** "부문들이 서로 많이 사고판다"와 "각자 자기 생산분 1.0만
갖고 있다"가 **구별되지 않습니다.** 그래서 자기 자신을 뺀 **타 부문 거래 비중**을
함께 냅니다. 두 지표는 분모(그룹 전체 파급)가 같아 합이 100%가 됩니다.

```
내부 기여     = (1/k) Σ_{q∈M} b(m, q)        ← 자기 자신 포함
자기 자신     = b(m, m) / k
타 부문 거래   = 내부 기여 − 자기 자신
그룹 외부     = Σ_{i∉M} b(i, ·) / k
내부 + 외부   = expectedTotal (교차검증 잔차 ≈ 1e-16)
```

### 구간 경계 (실측 분포)

2023년 연장표에서 만들 수 있는 그룹 **281개**(대→중 33 · 중→소 83 · 소→기본 165)를
전부 계산해 사분위수를 경계로 삼았습니다. **절대 기준이 아니라 이 자료 안에서의
상대 위치**이며, 화면에도 그렇게 명시했습니다.

| 지표 | 하위 25% | 중앙값 | 상위 25% | 상위 10% |
|---|---|---|---|---|
| 내부 비중 (자기 포함) | 48.7% | 55.3% | 62.2% | 69.6% |
| 타 부문 거래 비중 | 0.00% | 0.05% | 0.78% | 2.75% |
| 집중도 (k·HHI, 1=균등) | 1.36 | 1.71 | 2.12 | 2.96 |

**중요**: 처음에 "70~100% = 매우 높음"으로 제안했지만, 실측해 보니 70% 이상은
전체의 **10%뿐**이고 50~70%에 **60.8%가 몰려** 기준으로 쓸 수 없었습니다.
그래서 사분위 앵커로 바꿨습니다.

타 부문 거래가 대부분 1% 미만인 것은 계산 오류가 아니라 계수의 성질입니다.
자기 자신 1.0 다음이 직접 투입 관계(0.1 안팎)이고, 여기에 `1/k` 평균까지 내기
때문입니다. 그래서 **0.5%도 의미 있는 값**이며, 절대 크기보다 **그룹 간 상대 비교**로
읽어야 합니다.

### 화면 구성 (Q2 결정 사항)

모바일에는 hover가 없고 PDF·스크린샷에는 툴팁이 사라지므로, **설명을 항상 보이게**
두고 `?`는 보조로만 씁니다.

| 위치 | 내용 | 항상 보임 |
|---|---|---|
| 두 지표 카드 | 큰 숫자 + 판정 배지 + 3색 누적 막대 + 범례 | ✅ |
| 자동 판정 문장 | 최대 부문·최소 부문·균등 기준선을 **문장에 직접** 넣음 | ✅ |
| "종목 탐색에 어떻게 쓸까" | 그룹 결합도를 **종목 분산효과**로 번역 | ✅ |
| 표 마지막 열 | **타 부문 거래** + 균등 기준선(1/n) 열 | ✅ |
| `?` 버튼 | 상세 설명 4절(무엇/왜/기준선/작은 이유) 펼치기 | 데스크톱·모바일 모두 클릭 |

### 검증 기록

| 사례 | k | 내부 | 자기 자신 | 타 부문 | 판정 | 잔차 |
|---|---|---|---|---|---|---|
| C09 전자·광학기기 | 6 | 67.2% | 59.8% | 7.5% | 높음 · 매우 뚜렷 | 4.44e-16 |
| 27 철강1차제품 | 4 | 65.2% | 58.3% | 6.8% | 높음 · 매우 뚜렷 | 8.88e-16 |
| 51 토목건설 | 4 | 50.2% | 50.2% | **0.0%** | 보통 · 없음 | 4.44e-16 |

`51 토목건설`은 **타 부문 거래가 0**인 사례로, 내부 비중 50.2%가 전부 자기 자신임을
정확히 잡아냅니다. 이 경우 앱은 "내부 비중이 높아도 자기완결적이라기보다 각자
독립적"이라고 안내합니다.

## 5.5 STEP 1 이름으로 분류 찾기 (자동 단위 전환)

사용자는 "자동차"가 대분류·중분류·소분류·기본부문 중 **어디에 속하는지 모릅니다.**
그래서 STEP 1의 `분류 단위` 블록 **위**에 이름 검색을 두었습니다. 위치를 여기로 정한
이유는, 사용자가 "어느 단위를 골라야 하나" 하고 멈추는 지점이 정확히 그 자리이기
때문입니다. 흐름이 `① 이름으로 찾기 → 자동 결정·로드` / `② 아니면 단위 직접 고르기`가
되어 자연스럽습니다.

### 데이터 비용은 0입니다

분류표(`data/sector-tree.xlsx`, 4단계 661개 부문)는 **초기화 때 이미 메모리에
올라와 있습니다**(드릴다운에 쓰기 때문). 따라서 검색 자체는 **추가 다운로드가 없고**,
결과를 눌렀을 때만 그 단위의 투입산출표 파일을 받습니다. "굳이 애매한 기능"이 아니라
비용 대비 효과가 큰 기능입니다.

### 동작

1. 이름이나 코드를 입력하면 **4단계 전체**에서 찾습니다(예: `자동차` → 8건).
2. 각 결과에 **분류 이름 배지**(대분류/중분류/소분류/기본부문)와 **코드**, 그리고
   **상위 분류 경로**(`운송장비 › 자동차·운송장비`)를 함께 보여줍니다.
   → "이 산업이 어느 분류에 속하는가"가 한눈에 보입니다.
3. 결과를 누르면 그 단위 파일을 **자동으로 내려받아** 해당 부문을 선택하고
   분석 영역으로 이동합니다.

정렬은 `정확히 일치 → 앞부분 일치 → 포함` 순이고, 같은 점수면 **상위 분류를 먼저**
보여줍니다. 검색 결과가 24건을 넘으면 앞 24건만 표시하고 검색어를 좁히도록 안내합니다.

## 5.6 STEP 3 산업 검색 — 적용되지 않던 문제 수정

### 증상

`중분류`에서 `반도체`를 검색하면 오른쪽 산업 선택에 `31 · 반도체`가 나오는데,
**그것을 골라도 아래 분석이 갱신되지 않았습니다.** 반면 결과가 여러 개일 때는
동작했습니다.

### 원인

`<select>`는 목록을 다시 채우면 **첫 항목이 자동으로 선택**됩니다. 사용자가 그
첫 항목을 클릭하면 `value`가 **이미 그 값이라 변화가 없고**, 따라서 `change`
이벤트가 발생하지 않습니다. 결과가 여러 개면 두 번째 항목을 고를 때 `value`가
바뀌므로 우연히 동작했던 것입니다.

### 수정

| 상황 | 동작 |
|---|---|
| 결과 **1개** | 고를 것이 없으므로 **즉시 자동 적용**(`selectSector` 직접 호출) |
| 결과 **2개 이상** | 목록 맨 앞에 `— 산업을 고르세요 (n개) —` **빈 안내 항목**을 넣고 `value=''`로 초기화 → 실제 항목을 고르면 `value`가 바뀌어 `change`가 확실히 발생 |
| 결과 **0개** | `검색 결과 없음` 한 줄 + 안내 문구 |
| 검색어 **지움** | 안내 항목 없이 **전체 n개 목록 복원**, 현재 분석 중인 산업 선택 유지 |

### 검증 기록 (중분류 83부문)

| 시나리오 | 결과 |
|---|---|
| `자동차` 검색 (2건) | `count=3`(안내항목 포함), `value=""`, 목록 `[빈] · 40 자동차 · 82 자동차·소비용품…` |
| `40 · 자동차` 클릭 | `result=40 자동차` — **적용됨** |
| `철강1차` 검색 (1건) | `count=1`, 자동 적용 → `result=27 철강1차제품` |
| 검색어 지움 | `count=83`, 안내항목 없음, 현재 선택 유지 |
| 없는 검색어 | `count=1`(`검색 결과 없음`), 안내 문구 표시 |
| `자동차` 검색 → 중분류 40 클릭 (STEP 1) | 중분류 파일 자동 로드, `result=40 자동차`, 가로 넘침 0 |

## 6. 데이터 파일을 교체하려면

`data/manifest.json`만 수정하면 코드를 바꾸지 않고 파일을 교체할 수 있습니다.

```json
{
  "id": "large",
  "label": "대분류",
  "sectorCount": 33,
  "file": "./data/io-2023-large.xlsx",
  "sheet": "생산유발계수",
  "enabled": true
}
```

### 대표기업을 채우려면

`data/companies.csv`에 행을 추가합니다. **엑셀에서 열어 편집한 뒤 CSV(UTF-8)로 저장**하면 됩니다.

```csv
level,sector_code,sector_name,company_name,ticker,market,note
대분류,C09,"컴퓨터, 전자 및 광학기기",삼성전자,005930,KOSPI,반도체·전자기기 사업 기준 대응
```

| 컬럼 | 설명 |
|---|---|
| `level` | `대분류` / `중분류` (2단계에서 사용) |
| `sector_code` | 투입산출표의 부문 코드 (`C09`, `D`, …) — **이 값으로 매칭됩니다** |
| `sector_name` | 부문 이름 (표시용) |
| `company_name` | 종목명 |
| `ticker` | 종목코드 (6자리) |
| `market` | KOSPI / KOSDAQ / KONEX |
| `note` | 어떤 사업 기준으로 대응시켰는지 |

- 상장사가 없는 부문(공공행정·교육·국방 등)은 `ticker`를 비우고 `note`에 사유를 적으면, 앱이 **「상장 대표기업이 확인되지 않았습니다」** 로 표시합니다.
- 대분류 33개 부문에 대해 현재 등록되어 있습니다.

## 7. 구현상의 설계 결정

| 결정 | 이유 |
|---|---|
| **Excel을 브라우저에서 파싱** | 서버·DB 없이 GitHub Pages에서 동작. 원본 파일이 저장소에 그대로 남아 검증 가능 |
| **계수를 "직접 읽기"로 사용** | 한국은행 발표값과 100% 일치. 재계산은 교차검증 용도로만 사용 |
| **버튼을 눌러야 로딩** | 과제 점검항목 "버튼을 누른 뒤 자료가 로딩됨" 충족. 초기 화면이 즉시 뜸 |
| **파일은 필요할 때만 로딩** | 기본부문 파일이 11.5MB이므로 초기 로딩에서 제외 |
| **Chart.js 미사용** | 막대는 CSS로 그려 라이브러리·용량 부담을 줄임 |
| **계수 의미를 화면에 명시** | 단위·부호·자기 제외 이유를 사용자가 바로 알 수 있게 함 |

## 8. 읽을 때 주의할 점 (한계)

이 절은 과제 보고서의 **한계 및 해석상 유의점**에 해당합니다.

1. **계수는 생산액 기준 기술적 연관관계입니다.** 주가는 이익·밸류에이션·수급에 반응하므로, 연관산업이라는 사실이 **주가 동조를 보장하지 않습니다.** 이 앱은 투자 판단 도구가 아니라 **탐색 후보를 좁히는 도구**입니다.
2. **산업 규모 차이가 반영됩니다.** 생산유발계수는 금액 기준이므로 규모가 작은 산업은 계수도 작게 나옵니다.
3. **대표기업 매핑은 판단이 개입합니다.** 산업연관표의 부문과 상장사의 사업 범위는 1:1로 대응하지 않습니다. 하나의 부문에 여러 상장사가 걸리고, 한 기업이 여러 부문에 걸치기도 합니다. 현재 목록은 **시가총액 순위가 아니라 사업 대응 관계**를 기준으로 작성했습니다.
4. **종목코드의 정확성을 보증하지 않습니다.** 공개 자료를 기준으로 기입했으나, 투자 판단의 근거로 사용할 수 없습니다.
5. **연장표는 추정표입니다.** 2023년 연장표는 실측 확정표가 아니라 외삽·추정을 거친 표입니다.
